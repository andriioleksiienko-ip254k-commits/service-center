# Карта стану (Л 2.1)

> Цей розділ потрібно додати в `docs/component-architecture.md` (замість версії для кроків 1-5, якщо ви її вже вставляли).

## Значення, власники й споживачі

| Значення | Призначення | Початковий стан | Власник | Споживачі | Скидання |
|---|---|---|---|---|---|
| `services` | Предметні дані каталогу | Масив із `data/services.js` | Модуль даних, підключений у `App` | `ServiceSelectionProvider` і `CatalogContainer` через `items` | Не змінюється: фільтри, вибір і чернетка дані не чіпають |
| `detailsOpen` | Розгорнутий опис однієї картки | `false` | Конкретний екземпляр `ServiceCard` | Кнопка опису й абзац опису цієї ж картки | Повторне натискання; зникає при демонтуванні картки; перезавантаження |
| `query`, `availableOnly` | Параметри фільтрації каталогу | `''`, `false` | `HomePage` (викликає `useServiceFilters`) | `ServiceFilters` (значення полів), обчислення `visibleItems` | `resetFilters` |
| `selectedId` | Ідентифікатор вибраної послуги | `null` | `ServiceSelectionProvider` | `CatalogContainer` (позначка в картках), `RequestContainer` (`selectedItem`, `key`) | `clearSelection()` (кнопка «Скасувати вибір…»); перезавантаження |
| `draft` | Незбережена чернетка заявки: `deviceType`, `brand`, `model`, `problem` | Порожні рядки (`createEmptyDraft`) | `RequestPage` (форма й підсумок його бачать) | `RequestForm` (значення полів), `RequestSummary` | `handleReset` («Очистити поля»); нова послуга або скасування вибору (через `key`); перезавантаження |
| `document.title` | Зовнішня властивість браузера | Заголовок з `index.html` | Браузер; синхронізує ефект у `RequestPage` | Вкладка браузера | `cleanup` ефекту при зміні `title` і при демонтуванні |

## Похідні значення (окремого `useState` не мають)

| Значення | Як обчислюється | Чому не стан |
|---|---|---|
| `normalizedQuery` | `query.trim().toLocaleLowerCase('uk')` | Випливає з `query` |
| `visibleItems` | `items.filter(...)` за запитом і прапорцем | Випливає з даних і фільтрів |
| «Показано послуг» | `visibleItems.length` | Випливає зі списку |
| `selectedItem` | `items.find(item => item.id === selectedId)` у провайдері | Пошук у повному масиві, тому фільтр не скасовує вибір |
| `selected` у картці | `item.id === selectedId` | Картка не зберігає копію вибору |
| `title` для вкладки | `item ? 'FixIT Service: ' + item.name : 'FixIT Service'` | Випливає з `item`; ефект лише записує його в браузер |
| Підсумок чернетки | `draft[field].trim() \|\| 'Ще не вказано'` | Показує `draft`, нічого не зберігає окремо |
| Підпис кнопок | `detailsOpen`, `selected` | Випливають зі стану й props |

## Чого свідомо не зберігаємо

- Копію вибраного об'єкта або його назву поряд із `selectedId`.
- `visibleItems`, кількість результатів і текст підсумку в окремому стані.
- Окремий `useState(selected)` у картці та дублікат `draft` у `RequestForm` чи `RequestSummary`.
- Фільтри, розгортання описів і поля чернетки в контексті: вони потрібні одному споживачеві.

## Контракти подій

| Подія | Відправник | Власник стану | Що змінюється |
|---|---|---|---|
| `onSelect(id)` | `ServiceCard` | `ServiceSelectionProvider` (`selectService`) | `selectedId`, якщо `id` відомий |
| `onQueryChange(text)` | `ServiceFilters` | `HomePage` (`useServiceFilters`) | `query` |
| `onAvailableOnlyChange(flag)` | `ServiceFilters` | `HomePage` | `availableOnly` |
| `onReset()` у фільтрах | `ServiceFilters` | `HomePage` | `query`, `availableOnly`; вибір не чіпає |
| `onFieldChange(field, value)` | `RequestForm` | `RequestPage` | Лише одне поле `draft`, решта копіюється |
| `onReset()` у формі | `RequestForm` | `RequestPage` | Усі поля `draft`; вибір не чіпає |
| `onClearSelection()` | `RequestPage` | `ServiceSelectionProvider` (`clearSelection`) | `selectedId` стає `null`; чернетка зникає через `key` |

## Потік вибору (з Context API)

```
Натискання «Вибрати послугу» у ServiceCard
  onSelect(item.id)
    ServiceList -> HomePage -> CatalogContainer
      selectService(id) із useServiceSelection()
        ServiceSelectionProvider: перевірка id, setSelectedId(id)
          Нове відображення: споживачі контексту отримують нове значення
            CatalogContainer -> HomePage -> ServiceList -> ServiceCard (selected)
            RequestContainer -> RequestPage (item, key) -> нова форма і підсумок
              useEffect(title): синхронізація заголовка вкладки
```

## Область провайдера

```
App
 AppLayout           (поза провайдером: SiteHeader, MainNav, footer вибір не потребують)
  ServiceSelectionProvider
   CatalogContainer -> HomePage -> ServiceList -> ServiceCard   (props)
   RequestContainer -> RequestPage -> RequestForm, RequestSummary (props)
```

Контейнери читають контекст і передають картці, списку, формі та підсумку явні props, тому ці компоненти не залежать від провайдера.

## Правила часу існування

- Вибір і чернетка зберігаються, коли вибрану картку приховано фільтром.
- Повторний вибір тієї ж послуги чернетку не змінює (ключ той самий).
- Інша послуга або скасування вибору створюють нову порожню чернетку (інший `key` на `RequestPage`).
- «Очистити поля» скидає лише чернетку, вибір лишається.
- Розгортання опису належить екземпляру картки й зникає, коли картку прибрано з дерева.
- Перезавантаження сторінки повертає все до початкових значень; нічого не зберігається.

## Обґрунтування засобів керування станом

| Потреба | Засіб | Чому |
|---|---|---|
| Розгортання опису | Локальний `useState` у картці | Потрібне одному екземпляру |
| Пошук і доступність | Стан сторінки через `useServiceFilters` | Потрібні фільтрам і списку одного сценарію |
| Поля та підсумок чернетки | Підняття до `RequestPage` | Два сусідні компоненти мають бачити один об'єкт |
| Вибір між каталогом і заявкою | Context API з обмеженою областю | Один ідентифікатор узгоджує дві гілки; розв'язує передавання через `App` і готує до маршрутів Л 2.2 |
| Видимі записи й лічильники | Звичайні обчислення | Визначаються даними й фільтрами |
| Заголовок вкладки | `useEffect` | Синхронізація із зовнішньою властивістю браузера |

## Чи залишати Context API

Для поточного обсягу (два споживачі, один рівень вкладення) вистачило б піднятого до `App` стану, і така версія теж коректна. Context API залишено, бо:

1. каталог і заявка стають окремими сторінками в Л 2.2, де передавання вибору через props між маршрутами громіздке;
2. у контекст винесено лише вибір і дві дії, решта станів лишилась локальною;
3. провайдер охоплює лише робочу область, шапка й навігація поза ним.

Ціна: споживачі залежать від провайдера вище (хук без провайдера кидає помилку), а значення `value` створюється заново при кожному відображенні провайдера. Для такого малого сценарію це допустимо. Якщо в курсовій другий споживач так і не з'явиться, контейнери й провайдер можна повернути до версії з `useState` в `App`.
